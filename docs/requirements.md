# TicketFlow 要件定義書

## 1. プロジェクト概要

TicketFlowは、小規模な開発チーム向けのチケット管理システムである。

チケットを利用して、開発作業の内容、担当者、進捗、コメント、履歴などを管理する。

また、本システム自体の開発プロセスもチケット駆動開発で管理する。

## 2. 開発目的

以下を目的としてTicketFlowを開発する。

1. 開発タスクや不具合をチケット単位で管理する。
2. 実装、レビュー、テスト、完了までの進捗をチケットで管理する。
3. GitHub IssueやPull Requestとチケットを関連付ける。
4. チケットの変更履歴を記録する。
5. 本システムの開発そのものをチケット駆動開発で実践する。

## 3. 想定ユーザー

小規模なソフトウェア開発チームを想定する。

MVPでは複雑なユーザー認証や権限管理は実装せず、
チケット上で担当者、報告者、レビュアーを管理する。

## 4. 機能要件

### 4.1 チケット管理

以下の機能を提供する。

- チケットを作成できる
- チケット一覧を表示できる
- チケット詳細を表示できる
- チケットを編集できる
- チケットのステータスを変更できる
- チケットの優先度を設定できる
- チケットの担当者を設定できる
- チケットの期限を設定できる

### 4.2 チケット種別

チケットには以下の種別を設定する。

- Feature
- Bug
- Task

### 4.3 優先度

以下の優先度を設定する。

- High
- Medium
- Low

### 4.4 ステータス

以下のステータスを使用する。

- Open
- In Progress
- Review
- Testing
- Done
- Blocked

ReviewまたはTestingで問題が発生した場合は、
In Progressへ戻すことができる。

### 4.5 完了条件

チケットにはAcceptance Criteria（完了条件）を設定する。

担当者は、設定された完了条件を満たしたことを確認してから
チケットを完了（Done）とする。

### 4.6 コメント

チケットに対してコメントを登録できる。

コメントには以下の情報を記録する。

- コメント内容
- コメント作成者
- 作成日時

### 4.7 履歴

チケットに対する主要な変更を履歴として記録する。

対象とする変更は以下とする。

- チケット作成
- チケット編集
- ステータス変更
- 担当者変更
- コメント追加

### 4.8 GitHub連携情報

チケットに以下のGitHub情報を登録できる。

- GitHub Issue番号
- GitHub Pull Request番号

GitHub APIによる自動連携はMVPでは実装しない。

## 5. チケット項目

チケットには以下の項目を持たせる。

| 項目 | 内容 |
|---|---|
| Ticket ID | チケットを識別するID |
| Title | チケットタイトル |
| Description | 作業内容・説明 |
| Type | Feature / Bug / Task |
| Priority | High / Medium / Low |
| Status | チケットの進捗状態 |
| Assignee | 担当者 |
| Reporter | 起票者 |
| Reviewer | レビュアー |
| Acceptance Criteria | 完了条件 |
| Due Date | 期限 |
| GitHub Issue | 関連するGitHub Issue |
| GitHub PR | 関連するPull Request |
| Created At | 作成日時 |
| Updated At | 更新日時 |

## 6. 非機能要件

### 6.1 動作環境

Webブラウザから利用できるWebアプリケーションとする。

### 6.2 データ保存

Google Spreadsheetをデータ保存先として使用する。

### 6.3 使用技術

以下の技術を使用する。

- Google Apps Script
- Google Spreadsheet
- HTML
- CSS
- JavaScript
- Git
- GitHub

### 6.4 履歴管理

チケットの主要な変更履歴を記録し、
後から変更内容を確認できるようにする。

## 7. 対象外機能

MVPでは以下の機能を実装対象外とする。

- ユーザー認証
- 詳細な権限管理
- メール通知
- Slack通知
- AIによる自動分類
- 外部データベース
- GitHub APIによる自動連携

## 8. 開発方針

本システムの開発自体をチケット駆動開発で進める。

基本的な開発フローは以下とする。

GitHub Issue
↓
要件・設計
↓
実装
↓
Git Commit
↓
Pull Request
↓
レビュー
↓
テスト
↓
チケット完了

「チケットに記録されていない作業は原則として実施しない」
ことを開発方針とする。

## 9. MVP完成条件

以下を実装できた時点をMVP完成とする。

- チケットを作成できる
- チケット一覧を表示できる
- チケット詳細を表示できる
- チケットを編集できる
- ステータスを変更できる
- コメントを登録できる
- 変更履歴を確認できる
- Google Spreadsheetにデータを保存できる
- GitHub Issue番号をチケットに登録できる
